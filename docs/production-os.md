# 旅ログ Production OS

この文書は、Notionに登録された候補を実際のCanva投稿へ変換するProductionレーンの正本です。

## 0. 目的

その場所をまだ知らない人に、
「ここはどんな場所か」「何が良いのか」「行くなら何を知っておくべきか」
を写真中心で自然に伝える。

派手な広告クリエイティブではなく、
信頼できる旅行メディア型PRを目指す。

## 1. 入力

Production対象は次のいずれか。

- Notion「贅沢旅リサーチ帖」に登録された候補
- ユーザーが直接指定した施設・観光地・体験

Notion登録済み候補は制作承認済み。
スコアはメタデータであり、制作可否には使用しない。

## 2. 制作順

自動運用時:
- V2ではNotion登録済み候補を一から再制作する
- 未制作候補を古い順に処理
- 重複確認はV2専用Canvaフォルダ `FAHYuHEOty4` とNotion `制作世代=V2正式` の行だけで行う
- 同名の旧Canvaや旧完成行は無視し、V2の制作済み判定に使わない
- 新規候補も同じV2キューへ追加

ユーザーが場所を直接指定した場合:
- 指定案件を優先して処理してよい

## 3. Web再確認

制作直前に必ず確認する。

- 正式名称
- 所在地
- 営業 / 参拝 / 入場時間
- 定休日・休館・参拝休止
- 料金とその条件
- アクセス
- 予約要否
- 季節・工事・休止等の最新告知
- 施設の代表的な魅力
- 初見の人が誤解しやすい点

優先ソース:
公式サイト → 自治体 / 観光協会 → 公式予約 → 公式SNS / Press Room → 信頼できる補助情報。

## 4. 写真

最優先はユーザー提供写真。

追加が必要なら、利用条件が確認できる実写素材を探す。
「公式ページに掲載されている」だけで転載可能とは判断しない。

写真は「見栄え」だけでなく、投稿全体で場所が理解できるように選ぶ。

例:
- 全景
- 外観 / 入口
- 代表的な体験
- 客室 / 温泉 / 料理
- 周辺景観
- 細部
- 季節性
- アクセスの雰囲気

同じ構図ばかりにしない。

## 5. Gemini Pro第二レビュー

APIは使用しない。

制作前:
- Deep Researchで情報を独立確認
- 写真候補をアップロードし分類・採点
- 表紙候補とP2〜P5の役割を提案させる

制作後:
- Canva完成稿をPDF化
- Gemini ProにPDFを渡して視覚QA

Geminiの判断より、公式情報と本リポジトリのルールを優先する。

## 6. Canva制作

`docs/canva-rules.md` に従う。

基本:
- 4:5
- 5ページ
- 既存MASTERを使用
- 写真主役
- 装飾を足しすぎない
- 初見で場所の魅力が分かる
- 文章は短く

## 7. ページの役割

### P1: 一目で分かる表紙
その場所を象徴する最も強い実写1枚。

### P2: ここはどんな場所？
位置・特徴・代表的な魅力。

### P3: ここならでは
景色、体験、文化、食など独自性。

### P4: もう一つの魅力
写真だけでは分からない楽しみ方・名物・背景。

### P5: 行く前に知る
アクセス、時間、予約、注意事項、保存CTA。

施設によって順番やテーマを最適化してよいが、
「場所の理解 → 魅力 → 実用情報」の流れは崩さない。

## 8. PR文章

目標:
「すごい！」だけで終わらず「なぜ良いか」が分かる。

避ける:
- 世界一、絶対、人生変わる等の根拠なき最上級
- 実体験の捏造
- 写真と無関係な文章
- 情報の詰め込み

推奨:
- 短い見出し
- 1ページ1メッセージ
- 具体的な特徴
- 読んだ後に旅行判断しやすい情報

## 9. QA

Canva全5ページを必ず通しで確認。

- 5ページ揃っている
- 写真が実写
- AI生成 / AI補完された実景がない
- 写真利用条件に問題がない
- 文字切れなし
- 文字同士の重なりなし
- 重要被写体を文字で隠していない
- 写真と本文が一致
- ダミー文言なし
- 正式名称・所在地・アクセスが正しい
- 料金・時間が最新
- 表紙文字数ルール遵守
- 同一写真の不要な重複なし
- 派手な装飾で写真を損なっていない
- 初見ユーザーが「どんな場所か」理解できる
