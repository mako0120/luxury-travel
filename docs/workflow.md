# 投稿ステータス管理（ワークフロー）

## 正常系

```
RESEARCHING   候補をリサーチ中。まだ1件に絞られていない。
   ↓
DRAFT         BEST候補を1件選定し、投稿構成・コピーの草稿を作成した。
   ↓
FACT_CHECKED  施設情報（料金・営業状況・設備等）を2つ以上の独立情報源で確認した。
   ↓
ASSET_CHECKED 使用する画像すべての出典・著作権者・利用条件・確認日を記録し、
              転載権限が確認できた（できない画像は使用しない）。
   ↓
READY         キャプション・カルーセル構成・ハッシュタグまで完成し、投稿可能な状態。
   ↓
SCHEDULED     Publishing Queueに投稿予定日時を登録した（投稿ツール未接続時は予定日時のみ保持）。
   ↓
POSTED        実際にSNSへ投稿した（投稿ツール接続後のみ到達しうる）。
```

## 異常系（正常系のどの段階からでも遷移しうる）

- `NEEDS_REVIEW` — ファクトチェックで矛盾・不明点が残る、低評価レビューで無視できない懸念がある等、
  人間の判断が必要な場合。
- `NEEDS_ASSET_APPROVAL` — 使用したい画像の転載権限が確認できない場合。`READY` には進めない。
- `FAILED` — 候補として成立しない（除外基準に抵触、公式情報が取得できない等）ことが判明した場合。

## 運用ルール

- `READY` 未満のステータスで Publishing Queue に「投稿可」として登録してはいけない。
- `NEEDS_ASSET_APPROVAL` の投稿は、権利確認が取れた画像に差し替えるか、人間が利用承認するまで `READY` にしない。
- 状態を後退させる場合（例: `FACT_CHECKED` → `NEEDS_REVIEW`）は `post.json` の `status_history` に理由を残す。
